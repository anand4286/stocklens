Architecture API
Demo mode: prices, news and fundamentals are synthetic and generated per ticker. Connect your own data keys to see real markets.

How StockLens is built

A single FastAPI service, a pure analytics core, a bounded AI agent, and a persistence layer — behind an edge that terminates TLS and rate-limits, with egress restricted to three named hosts.

System architecture

Request path

The edge terminates TLS and applies the first rate limit. The app enforces its own limit, security headers and optional bearer-key auth regardless, so a misconfigured proxy does not leave it open. Tickers are validated against ^[A-Z]{1,5}([.-][A-Z]{1,2})?$ before they reach any upstream URL.

One report per symbol is built from the data facade and handed to the page, the agent and the evaluation harness alike — they can never disagree about a number.

Agent loop

The agent gets six read-only tools bound server-side to one symbol, plus submit_report. No tool takes a ticker, URL or query. The loop has a step ceiling, handles every stop reason, re-validates the submission with Pydantic and checks each cited figure against what the tools actually returned.

Runs are cached per symbol, capped per day from the database, rate-limited per client, and written to an append-only audit table with tokens, latency and the full tool trace.

Security layers

Strict CSP with no inline script, HSTS, frame denial, nosniff. Secrets are SecretStr and never logged. Constant-time key comparison. Non-root, read-only container with all capabilities dropped. Network policy allows ingress only from the ingress controller and egress only to DNS, the database and three HTTPS hosts.

Deploy anywhere

Templates ship for Docker Compose (app, PostgreSQL, Caddy with automatic TLS), a hardened systemd unit with nginx and ufw on a plain VM, Kubernetes with NetworkPolicy, HPA and PDB, Google Cloud Run, AWS App Runner/ECS, and Azure Container Apps.
