The architecture

A model that keeps score

Most stacks end at "show the number". This one is organised around what happens next.

  1. ScoreRegime first, then eight evidence families and a blend whose contributions add up.
  2. CommitP(up in 21 sessions) and a 1σ range, with the features and model version.
  3. LedgerAppend-only. One per symbol per day, written before the outcome exists.
  4. ResolveTwenty-one sessions later. Write-once — never revised.
  5. GradeBrier skill, a reliability curve, a t-test over independent blocks.
  6. Earn the weightsPicked defaults stay labelled "picked" until the record says otherwise.

Live calibration

When the model says 60%, does it happen 60% of the time? The simulated record over a fixed basket, graded the same way as the live ledger.

Why the honest answer is "no skill"

On demo data — a factor model with no expected-return signal — the correct verdict is no skill, and the tests make sure it stays that way. A 5-stock random basket once earned "skill" on a plain confidence interval. The block t-test now refuses it, because twelve forecasts on one morning share one market.

That is the point of the architecture. A tool that finds an edge in noise is broken, and this one checks itself for it on every commit.
